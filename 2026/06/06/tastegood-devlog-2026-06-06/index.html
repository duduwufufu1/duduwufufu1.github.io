今日完成

1. 修复 add-record 页全部交互失效（v1.0.1）

根因: Codex 写入时 WXML 事件名和 JS 函数名用了两套命名规范，所有 bindtap 找不到对应函数，整个页面静默失效。

修复 8 处函数名 + 1 处评分逻辑：

按钮/操作 WXML 引用 原先 JS 函数名 修复为
📸 上传图片 handleAddPhoto addPhoto ✅ handleAddPhoto
❌ 删除图片 handleRemovePhoto removePhoto ✅ handleRemovePhoto
⭐ 评分 onRatingChange setRating(用了错的e.currentTarget.dataset) ✅ onRatingChange + e.detail.rating
📍 地图搜索位置 handleSearchLocation searchLocation ✅ handleSearchLocation
🗺️ 点击地图选点 handleMapTap onMapTap ✅ handleMapTap
🏷️ 标签切换 handleToggleTag toggleTag ✅ handleToggleTag
➕ 添加自定义标签 handleAddCustomTag addCustomTag ✅ handleAddCustomTag
💾 保存提交 handleSubmit submit ✅ handleSubmit

2. 新增入口迁移（城市首页）

  • 地图页（index）移除底部导航栏的 + 新增按钮及对应 JS 函数
  • 城市首页（cities）添加右下角浮动按钮（FAB），红色圆形 #c84632，带阴影悬浮效果
  • 点击跳转 /pages/add-record/add-record

3. 修复个人页（profile）交互

同样是 Codex 命名不一致问题：
- previewPhoto → handlePreviewPhoto：照片墙点击调用 wx.previewImage 全屏查看
- goDetail → handleGoDetail：最近记录点击跳转 /pages/detail/detail?id=xxx

4. 修复个人页图片加载慢/不加载

根因: cloud:// 文件 ID 直接作为 <image> src 使用，部分图片加载不稳定。

修复: 构造 photoWall 和 recentRecords 后，提前用 wx.cloud.downloadFile() 批量下载 cloud:// 文件为本地临时路径，下载失败时回退原路径。

5. 微信开发者工具 CLI 联调

  • 发现开发者工具安装在 D:\微信web开发者工具\
  • CLI 工具 cli.bat 可用，支持 open/upload/preview/islogin 等命令
  • 首次使用时需先开启服务端口（echo y | cli.bat islogin）
  • 成功上传 v1.0.1、v1.0.2 和 v1.0.3 到微信后台

6. 地图标记重新设计 — 大头针风格（v1.0.3）

  • 用 Pillow 生成三枚新标记图标，96×112px
  • marker-prov.png（省份）：深棕 #2f281f + 金色星星
  • marker-food.png（记录）：红色 #d8512f + 白色星星
  • marker-pick.png（选位置）：青绿 #276c78 + 白色星星
  • 经典地图针形：圆形顶部 + 渐尖底部，带阴影和高光
  • 替换了原先圆钝的 pin 设计（修复"猪鼻子"问题）

7. 城市卡片文字居中（无图片时）

  • 城市页（cities）每张城市卡片添加 flex 居中布局
  • 无图片展示时，文字内容（拼音缩写 + 城市名 + 店铺数）整体垂直居中
  • 有图片时图文整体居中，视觉更整齐

8. 敏感数据抽离（v1.0.4）

  • 新建 utils/config.js，存放腾讯地图 Key 和云环境 ID
  • utils/config.js 已加入 .gitignore，不会上传 GitHub
  • 新建 utils/config.template.js 作为空模板，提交到 Git
  • 更新 app.js（云环境 ID）和 add-record.js（地图 Key）改为从 config 读取

遇到的问题

Codex 命名不一致（重复出现）

add-record 页和 profile 页都出现了 WXML 事件名与 JS 函数名不匹配的问题。这是 Codex CLI 通过 PowerShell 写入文件时的已知问题——同一文件内的 WXML 和 JS 用不同命名规范生成。

预防: 用 Codex 写代码后，必须检查 WXML 的 bindtap / bindinput 与 JS 的对应函数名是否一致。
