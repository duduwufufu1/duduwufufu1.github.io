TasteGood 开发日志 - 2026-06-08

今日主题

本次开发围绕 TasteGood 的“记录体验闭环”继续推进，重点完成了两个方向：

  1. 详情页支持同一地点多次回访记录聚合展示。
  2. 优化未登录状态体验，让用户在添加记录前先获得清晰登录引导。

同时修复了一个城市统计问题：同一地址的重复回访不应让城市店铺数字增加。

一、详情页：同址回访记录聚合

详情页原本只展示当前单条记录。现在进入某条记录后，会自动查询当前用户在同一地点/同一店铺的其他记录，并用回访卡片展示完整历史。

匹配规则

同一地点判断采用保守规则，避免误合并：

  • 优先使用可靠地址：city + address
  • 如果地址为空，或地址是“已选择位置...”这类占位地址，则使用：city + name
  • 不使用复杂地理距离算法，避免不同店铺被误合并

UI 展示

详情页新增“回访记录”区域：

  • 多次记录时显示：回访记录 · N 次
  • 单次记录时显示：本次记录
  • 使用 swiper 展示每次记录
  • 每张卡片展示：
  • 第 N 次
  • 时间
  • 一句话评价
  • 菜品 / 价格
  • 星级
  • 标签
  • 具体评价

顶部图片轮播也改为同一地点所有记录的图片合集，并自动去重。这样即使当前记录没有图片，也可以展示同一地点历史记录里的图片。

二、修复城市统计：重复地址不再增加店铺数

在添加同一地址的新回访记录后，城市页原本会把记录条数直接加一，导致“几家店铺”的数字被错误抬高。

根因

城市页、首页地图、个人页足迹原先都按 record 条数统计。

但实际 UI 语义是“店铺数 / 地点数”，而不是“记录数”。多次回访同一家店时，应该只算一个地点。

修复方案

新增 utils/record-place.js，统一封装地点去重逻辑：

  • getPlaceKey(record)：生成地点唯一 key
  • isSamePlace(currentRecord, record)：判断两条记录是否属于同一地点
  • groupRecordsByPlace(records)：按地点聚合记录
  • getMergedImages(records)：合并同地点图片

修改范围：

  • 城市页：城市卡片 count 改为唯一地点数
  • 城市页顶部：文案从“记录”改成“店铺”
  • 首页地图：全国/省份/城市层级 marker 统计按唯一地点计算
  • 城市地图层级：同地址只生成一个 marker
  • 个人页足迹：城市热力不再因重复回访虚高
  • 详情页：复用统一同地点判断逻辑

三、未登录体验优化

添加记录页之前的体验比较突兀：用户可以进入表单填写，但保存时才提示需要登录。

现在改为：用户未登录时进入添加记录页，先看到一个产品化登录引导卡，不再展示整套表单。

添加记录页

未登录时展示：

  • 小标题：PRIVATE NOTEBOOK
  • 主标题：先登录，再记录美味
  • 说明：登录后会把每一次探店安全保存到你的私人美食地图。
  • 标签：私密保存、同步足迹
  • 主按钮：去我的页登录

点击按钮会跳转到个人页登录。

已登录时，原添加/编辑记录流程保持不变。

个人页登录卡片

个人页默认头像从简单“味”字升级为 CSS 渐变徽章：

  • 圆形渐变底
  • 内部“味”字
  • 小装饰点
  • 外层光晕和边框

未登录状态文案改为：

  • 开启你的美食地图
  • 登录后同步并只展示你的记录

按钮样式也改为更明显的主色胶囊按钮，保持 warm/card 美食杂志风格。

五、下一步建议

下一步可以继续做“登录后首屏体验优化”：

  • 首页/城市页未登录时展示更明确的登录引导

  • 最近记录为空时给出更有设计感的空状态卡片
