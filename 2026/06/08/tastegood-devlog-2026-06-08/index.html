今日完成

1. 详情页：同址回访记录聚合（v1.0.6）

详情页原本只展示当前单条记录。现在进入某条记录后，会自动查询当前用户在同一地点/同一店铺的其他记录，并用回访卡片展示完整历史。

同一地点匹配规则:
- 优先使用可靠地址：city + address
- 如果地址为空，或地址是“已选择位置...”这类占位地址，则使用：city + name
- 不使用复杂地理距离算法，避免不同店铺被误合并

UI 展示:
- 多次记录时显示：回访记录 · N 次
- 单次记录时显示：本次记录
- 使用 swiper 展示每次记录
- 每张卡片展示第 N 次、时间、一句话评价、菜品/价格、星级、标签和具体评价
- 顶部图片轮播改为同一地点所有记录的图片合集，并自动去重

2. 修复城市统计：重复地址不再增加店铺数（v1.0.7）

添加同一地址的新回访记录后，城市页原本会把记录条数直接加一，导致“几家店铺”的数字被错误抬高。

根因: 城市页、首页地图、个人页足迹原先都按 record 条数统计，但实际 UI 语义是“店铺数 / 地点数”。多次回访同一家店时，应该只算一个地点。

修复方案: 新增 utils/record-place.js，统一封装地点去重逻辑。

核心方法：
- getPlaceKey(record)：生成地点唯一 key
- isSamePlace(currentRecord, record)：判断两条记录是否属于同一地点
- groupRecordsByPlace(records)：按地点聚合记录
- getMergedImages(records)：合并同地点图片

修改范围：
- 城市页：城市卡片 count 改为唯一地点数
- 城市页顶部：文案从“记录”改成“店铺”
- 首页地图：全国 / 省份 / 城市层级 marker 统计按唯一地点计算
- 城市地图层级：同地址只生成一个 marker
- 个人页足迹：城市热力不再因重复回访虚高
- 详情页：复用统一同地点判断逻辑

3. 未登录体验优化（v1.0.8）

添加记录页之前的体验比较突兀：用户可以进入表单填写，但保存时才提示需要登录。

现在改为：用户未登录时进入添加记录页，先看到一个产品化登录引导卡，不再展示整套表单。

添加记录页未登录卡片:
- 小标题：PRIVATE NOTEBOOK
- 主标题：先登录，再记录美味
- 说明：登录后会把每一次探店安全保存到你的私人美食地图。
- 标签：私密保存、同步足迹
- 主按钮：去我的页登录

个人页登录卡片:
- 默认头像从简单“味”字升级为 CSS 渐变徽章
- 未登录状态文案改为：开启你的美食地图、登录后同步并只展示你的记录
- 按钮样式改为更明显的主色胶囊按钮

4. 列表页：按店铺聚合展示回访信息（v1.0.9）

列表页原本按记录条数展示。这样同一家店多次回访时，会出现多张几乎一样的卡片，信息密度偏低。

现在列表页改为按“店铺 / 地点”聚合展示：
- 同一地点只展示一张卡片
- 卡片代表记录取该地点最新一次记录
- 卡片新增回访标签：首次记录 / 已回访 N 次
- 卡片新增一句话标题 reviewTitle
- 卡片新增招牌菜 / 菜品 dishName
- 卡片新增价格 price
- 星级、城市和地址继续保留

交互价值: 列表页更像“店铺清单”，详情页负责展示“同一家店的多次回访历史”。

文案一致性: 首页地图城市选择面板从 条记录 改为 家店铺。

5. 修复城市页跳转地图层级错误（v1.0.10）

从城市页点击某些城市，尤其是省会城市时，进入地图后会错误显示为省份层级，而不是城市层级。

根因: 城市页点击城市后，通过 app.globalData.selectCity 和 selectCenter 把目标城市传给首页地图。首页地图 onShow() 读取到目标城市后，原先直接使用 setData() 设置 level: "city"、mapScale: 12 和 mapCenter。

但首页地图已有 setMapLevel() 方法，用来在切换层级时临时开启 ignoreNextScaleChange。直接 setData() 没有开启这个保护，地图组件进入后触发 regionchange，syncLevelByScale() 根据地图缩放值又把城市层级切回省份层级。

修复方案: 将城市页跳转入口改为使用 setMapLevel(..., () => this.loadRecords())，让初始地图缩放变化不会误触发层级回退。

6. 个人页：最近记录显示“第几次记录”（v1.0.10）

为了让“回访”概念在个人页也能被感知，最近记录新增了“第 N 次记录”标签。

计算方式:
1. 使用 recordPlace.groupRecordsByPlace(records) 按同一地点分组
2. 每个分组内按 createdAt 从早到晚排序
3. 给每条记录计算 visitIndex
4. 最近记录仍然展示最新 5 条，但每条记录额外带上 visitText: 第 N 次记录

UI 展示: 最近记录卡片中，店名右侧新增胶囊标签，例如：第 1 次记录、第 2 次记录。
